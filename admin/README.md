# ממשק ניהול הדו״חות — בפיתוח

ממשק ניהול ופונקציית Neon בענף הפיתוח. טרם בוצעה בדיקה מלאה של כניסה, העלאת תמונות ופרסום, ואין להשתמש בנתונים אמיתיים עד להשלמתה.

## פיתוח

```bash
cd admin
npm ci
npm run build
node test.mjs
node --experimental-test-module-mocks --test integration.test.mjs
```

הבנייה יוצרת `build/index.mjs`, `build/index.html` ו־`build/app.js`. הפונקציה בודקת JWT מול JWKS של Neon Auth, ולאחר מכן מחייבת משתמש פעיל בטבלת `app_users`. יצירת חשבון ב־Neon Auth אינה מעניקה הרשאות באופן אוטומטי. אין לאשר משתמש בלי לוודא את זהותו. הפונקציה משתמשת במשתני Neon המוזרקים בסביבת Function, ובדליים הפרטיים של ענף הנתונים.

## יכולות שבקוד

שמירת טיוטה לכל 11 האזורים והערות נלוות, העלאת צילומי JPEG/PNG/WebP לאחסון פרטי, שליחה לאישור ושני אישורים נפרדים, לפחות אחד מהם מרכז, שיכול להשתתף כמתנדב. רק רכז יכול להפעיל פרסום. הדו״ח לא נערך במצבי אישור, ובקשת פרסום יכולה להפעיל Render deploy hook שנשמר כמשתנה שרת `RENDER_DEPLOY_HOOK` בלבד. קבלת hook אינה אימות שהפריסה הסתיימה.

בעת בניית Pelican אפשר להפעיל `python scripts/export_reports.py` לפני הבנייה. נדרשים `BPARK_EXPORT_ENABLED=1`, `BPARK_READ_DATABASE_URL` לקריאה בלבד, ומשתני AWS של Neon עם הרשאות קריאה לאחסון. רק דו״חות מאושרים שעבורם נתבקשה פעולה או שסומנו כפורסמו מיוצאים לאתר. תמונות מיוצאות מחדש כ־JPEG ללא נתוני EXIF. אם הייצוא נכשל, הבנייה חייבת להיכשל כדי לא לפרסם מידע חלקי.

## לפני שימוש אמיתי

- להשלים וידוא זהות ויצירת גישה למשתמשים; לא להסתמך על דוא״ל לא מאומת.
- לבדוק מקצה לקצה כניסה, הרשאות, עריכה, העלאה, אישורים, ייצוא ופריסה, כולל כשלי רשת ושני משתמשים במקביל.
- לקבוע כיצד מזהים ומציגים הצלחה או כישלון של הפריסה. כרגע נשמרת בקשת פרסום בלבד, ללא אימות תוצאת הבנייה.
- להגדיר חשבון מסד וגישת אחסון לקריאה בלבד לבניית האתר, ולהגדיר סודות בסביבת Render ללא חשיפה לדפדפן או לריפו.
- להוסיף ממשק ניהול לחומרי התכנון הקבועים. רכז יכול להחזיר דו״ח לעריכה לפני שנתבקש פרסומו.
- להשלים בדיקת תמונה מלאה ומגבלות עומס, ולנטר כשלי ניקוי של אובייקטים יתומים.
- לבדוק העלאה, תצוגה, תאריך ותיאור של צילומים במכשיר אמיתי; לבדוק התנגשות עריכה וסגירה עם שינויים לא שמורים.
